## §R2 Precise definition

Name-level (or calendar-season) state: calendar distance to the next scheduled earnings release is small AND implied vol is elevated versus the name's own history (IV rank/percentile over 252 sessions [example]). IV crush after the print is the release mechanism. Timestamp accuracy is load-bearing: after-hours vs before-open matters, and close-to-close event returns do not demonstrate intraday tradability.

### Normative detection pseudocode

Pseudocode is normative; prose is commentary. `cfg` holds the §R0.2 parameters.
Hysteresis memory `prev` is carried per name and reset only on HALTED.

```
function detect(state, events, cfg) -> list[RegimeState]:   # causal; label at t uses events[:t+1] only
    mem = {}   # name -> prev label
    out = []
    for e in events (ascending event_ts):
        ts = e.ts_ns; name = e.name
        if e.market_state == HALTED:
            mem.pop(name, None)                 # [default] reset across reopen; discard contributions
            out.append(UNKNOWN(ts)); continue
        if e.market_state == AUCTION:
            out.append(hold(mem.get(name), DEGRADED)); continue
        if e.market_state == CLOSED:
            out.append(OFF(ts)); continue
        if not e.calendar_confirmed:           # F1
            out.append(UNKNOWN(ts)); continue  # memory kept: transient feed error
        (d, iv) = (e.d_days, e.iv_pct)
        if not (isfinite(d) and isfinite(iv)): # F2
            out.append(UNKNOWN(ts)); continue  # memory kept; never interpolate
        if abs(e.d_days_dual - d) > cfg.dual_tol:   # F3, dual_tol = 0.5 days [fixed]
            out.append(UNKNOWN(ts)); continue  # announced vs actual timestamp disagree
        label = transition(d, iv, mem.get(name), cfg)
        mstate = DEGRADED if e.lookback_n < cfg.L_min else OK   # split-truncated IV window
        mem[name] = label
        out.append(RegimeState(R035, label, d, "1.1.0", data_vintage, ts, mstate, cfg.min_lag_bars))
    return out

function transition(d, iv, prev, cfg) -> label:   # [example] thresholds; calibrate per §R3
    if d < 0: return NORMAL                        # [default] the print has passed
    if prev == PRE_EARNINGS:
        if d <= cfg.D + cfg.h_d and iv >= cfg.ivp_crit - cfg.h_ivp:
            return PRE_EARNINGS                    # hysteresis hold
    elif prev == WATCH:
        if d <= cfg.D and iv >= cfg.ivp_crit: return PRE_EARNINGS
        if d <= cfg.D_watch + cfg.h_d: return WATCH
        return NORMAL
    else:  # NORMAL / None / post-reset: strict entry, no hysteresis credit
        if d <= cfg.D and iv >= cfg.ivp_crit: return PRE_EARNINGS
        if d <= cfg.D_watch: return WATCH
        return NORMAL
    # exited PRE_EARNINGS: fall to WATCH band (with hysteresis) or NORMAL
    if d <= cfg.D_watch + cfg.h_d: return WATCH
    return NORMAL
```

**Edge cases (all pinned in fixtures/tests):**

- **Missing bars / gaps:** mask, no interpolation; the ts gap is visible in `computed_at`; the percentile uses only available sessions, and `lookback_n < L_min` forces `DEGRADED`.
- **Halts:** per §R0.5 — freeze, emit `UNKNOWN`, reset hysteresis memory; reopen requires re-entry through the strict entry rule (conservative [default]).
- **Corporate actions:** an unadjusted split inside the IV lookback truncates `lookback_n`; with `lookback_n < 126` [default] the label is still emitted but `module_state = DEGRADED`. Never silently mix adjusted and unadjusted IV.
- **Announced vs actual timestamp (BMO/AMC):** the dual calendar (`d_days_dual`) must agree within `0.5` days [fixed]; disagreement → `UNKNOWN` (F3) until reconciled.
- **Post-print (`d < 0`):** `NORMAL` [default] — the IV-crush belongs to the release, not to a new pre-earnings build-up.
- **F1/F2/F4 UNKNOWN rows keep hysteresis memory** (transient), but a HALTED row resets it (structural break) — [default].

## §R3 Exact calculation

Calendar distance `d = T_e − t` (calendar days, signed). IV rank over a
252-session [example] lookback:

$$\mathrm{IVR}_t = 100 \times \frac{\#\{s \in \text{trailing 252} : IV_s \le IV_t\}}{252}$$

Strict entry: `EARN_t = 1[d ≤ D] · 1[IVP_t ≥ IVP_crit]` with `D = 2` [example],
`IVP_crit = 90` [example]. Hysteresis (§R2): once `PRE_EARNINGS`, hold while
`d ≤ D + h_d` and `IVP ≥ IVP_crit − h_ivp` (`h_d = 1` [example], `h_ivp = 10`
[example]); exit otherwise. Worked check: reports in `2` days, ATM IV at the
90th [example] percentile → `d = 2 ≤ 2` and `IVP = 90 ≥ 90` → PRE-EARNINGS.

*Formula tag: [example] — constants inside this formula inherit it per the tag law
(Appendix i v1.0.0); worked-check numbers carry their own tags.*

**Data inputs.** Company earnings calendar (with report session); ATM IV (or IVX) time series.

**Cadence.** Daily; intraday on report days.

**Threshold bands (entry / hysteresis exit).**

| Condition | State | Tag |
|---|---|---|
| entry: `d ≤ 2`, `IVP ≥ 90` | PRE_EARNINGS | [example] |
| hold: `d ≤ 3`, `IVP ≥ 80` (only from PRE_EARNINGS) | PRE_EARNINGS | [example] |
| `d ≤ 5` (entry from NORMAL) / `d ≤ 6` (hold from WATCH) | WATCH | [example] |
| `d < 0` | NORMAL (print passed) | [default] |
| else | NORMAL | [example] |

### Detection-calibration recipe (all thresholds — no magic numbers)

Every `[example]` threshold above ships with the grid, objective, and OOS
selection that produced it; re-run before production use.

| Parameter | Grid [example] | Objective / selection |
|---|---|---|
| `D` | {`1`, `2`, `3`} | see below |
| `D_watch` | {`4`, `5`, `7`} | see below |
| `ivp_crit` | {`75`, `80`, `85`, `90`} | see below |
| `h_d` | {`0`, `1`, `2`} | see below |
| `h_ivp` | {`5`, `10`, `15`} | see below |
| `L` | {`126`, `252`} | longer wins unless a split truncates; `L_min = 126` [default] fixed |

- **Data:** per-name daily bars + announced AND actual earnings timestamps + ATM IV series; minimum `3` years [default] ≈ `12` earnings cycles [default]; corporate-action-adjusted IV only.
- **Objective (primary):** maximize the gated downstream T-module's OOS net Sharpe under this regime's cost-interface record; **stability guard:** reject configs whose PRE_EARNINGS coverage changes by > `10`% [default] when all earnings timestamps are jittered ±`1` day (Adversary date-shift test) — the window must follow the actual timestamp, not the grid.
- **OOS selection:** walk-forward, `12`-month train / `3`-month test [default], embargo gap `5` bars [default] after each earnings window; selection metric computed on the test folds only; never select windows ex post (F5).
- **Re-cal cadence:** quarterly [default]; immediately on calendar-vendor methodology change or IV-vendor series change (Gate).
- **Logging:** the winning config plus its (grid, metric, OOS folds) goes in the decision log (Appendix g v1.0.0); shipping a threshold without its calibration record fails review.

| State | Spread × | Impact × | Borrow × | Fee add (bps) | Applies when |
|---|---|---|---|---|---|
| PRE_EARNINGS | `2.0` | `1.5` | `1.0` | `0.0` | market makers widen into the print; thin book [example] |
| WATCH | `1.25` | `1.1` | `1.0` | `0.0` | mild pre-window widening [example] |
| NORMAL | `1.0` | `1.0` | `1.0` | `0.0` | identity |

**Which components scale, and why.** Spread and impact scale: liquidity providers
widen quotes and the book thins into a known binary event — the dominant,
mechanically expected effect. Borrow does **not** scale (`1.0` [default]):
stock-loan fees do not mechanically spike on earnings for general-collateral
names; hard-to-borrow names are a name-level borrow-desk input, not a regime
effect. Exchange/regulatory fees do **not** change on earnings days
(`fee_add_bps = 0.0` [default]). All multipliers `[example]` unless tagged
otherwise — calibrate per venue; the record is versioned with
`estimator_version` and every application is decision-logged (Appendix g
v1.0.0). Note: post-print IV crush is mark-to-market decay on long premium,
not a cost — it belongs in the S/T P&L, never in this record.

**Application rule.** `apply PRE_EARNINGS (or WATCH) multipliers to the name's expected_cost_bps inputs; else identity`

**Honest DEGRADED/UNKNOWN behavior.** Downstream gates must treat `UNKNOWN`
restrictively: degrade-direction strategies (overnight holds) veto entry while
`UNKNOWN`; amplify-direction strategies (PEAD) apply no amplification while
`UNKNOWN`. `DEGRADED` labels are usable but must be down-weighted (no new
sizing-up on a `DEGRADED` label). `UNKNOWN` never silently becomes the previous
label's cost multipliers — the cost interface applies the `NORMAL` (identity)
record while the regime is `UNKNOWN` [default].
