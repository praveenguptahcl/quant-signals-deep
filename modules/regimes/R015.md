# R015 — Tick-constraint regime

Whether the instrument is tick-constrained: `TickBind = fraction of quotes with (ask − bid) == tick`. Binding ticks change queue dynamics entirely — time priority dominates price priority, and the grid (not the economics) sets the inside quote. Provenance **[D]**.

### R0.5 Lag contract (mandatory)

- **Indicator causal rule:** the indicator at time `t` is computed using only
  data with `event_ts ≤ t`. Bar-close values of bar `t` are unavailable until
  bar `t` finalizes.
- **Gating rule:** a regime label computed at `t` may gate a signal evaluated
  at `t` **only for trades executable at `t+1` or later** — never for fills
  inside bar `t`.
- **Backtest lag:** any backtest conditioning on this regime must lag the
  label by ≥ `1` bar [default] (min_lag = `1` bar [default]; TickBind at t uses quotes ≤ t; routes t+1+ flow).
- **Adversary check (no-lookahead):** the test suite asserts
  `label_ts > indicator_ts` for the earliest gated trade and that appending a
  synthetic breakout bar does not move the trailing percentile used at `t`.
- **unknown_behavior:** `UNKNOWN` is restrictive — downstream halves size /
  widens stops / stands down; never treated as benign (F1).

## §R1 Precise definition

TickBind_T = (1/T)·Σ 1{Ask_t − Bid_t = τ}, τ = $0.01 under Reg NMS Rule 612 [documented]. Cross-check [documented RB-list]: trade-price clustering — >80% of trades at round ticks corroborates the constrained state.

## §R2 Exact calculation

$$\text{TickBind}_T = \frac{1}{T}\sum_{t=1}^{T} \mathbf{1}\{Ask_t - Bid_t = \tau\} \quad\text{[documented]}$$

Worked example [documented Grok RB2]: spreads `1,1,2,1,1,1,3,1,1,2` cents → `7/10 = 0.70` ⇒ tick-constrained. Bands [example]: `≥ 0.7` constrained · `≤ 0.3` unconstrained · else intermittent.

**Data inputs.** NBBO (or BBO) quote tape with bid/ask/timestamps; trade prints for the clustering cross-check.

**Cadence.** daily label; intraday refresh.

**Threshold bands.**

| Condition | Label | Tag |
|---|---|---|
| `≥ 0.7` | tick-constrained (queue games exist) | [example] |
| `0.3–0.7` | intermittent | [example] |
| `≤ 0.3` | tick-free | [example] |

Bands are `[example]`; the documented content is the TickBind definition and the O'Hara–Zhong regime concept.

## §R3 Efficacy modulation

| Affected family | Direction | Mechanism |
|---|---|---|
| Queue-position / latency | **amplifies** | only exist in tick-constrained names (queues form because price cannot improve); die in tick-free names |
| Spread-capture market making | **amplifies then inverts** | improves when constrained (1-tick spread is capturable); dies when a constrained name becomes unconstrained (e.g. after a split — edge halves [documented]) |
| Penny-jumping / 'improve by one tick' | **inverts** | dies when one tick is the whole spread |

## §R5 Cost interface: regime state → cost-function adjustment

Tick-constrained names have capturable 1-tick spreads: the adjustment favors maker flow and widens the assumed queue-wait cost; unconstrained names get taker pricing.

```python
def cost_adjustment(rsv, base):
    adj = dict(base)
    adj['trade_ok'] = True
    if rsv['state'] == 'constrained':
        adj['maker_ok'] = True        # [default] queue games exist
        adj['spread_mult'] = 0.5      # [example] 1-tick capturable
    elif rsv['state'] == 'unconstrained':
        adj['maker_ok'] = False       # [default] spread absorbs edge
        adj['spread_mult'] = 1.5      # [example]
    else:
        adj['maker_ok'] = True        # [default]
        adj['spread_mult'] = 1.0      # [default]
    return adj
```
