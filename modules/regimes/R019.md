### R0.5 Lag contract (mandatory)

- **Indicator causal rule:** the indicator at time `t` is computed using only
  data with `event_ts ≤ t`. The settled print of interval `t` is unavailable
  until the venue's settlement timestamp passes.
- **Settled-only rule:** labels are computed from **settled** prints only.
  Predicted / intra-interval funding estimates are telemetry, never gating
  input (Gate rejects estimate-gated labels).
- **Gating rule:** a regime label computed at `t` may gate a signal evaluated
  at `t` **only for trades executable at `t+1` or later** — never for fills
  inside bar `t`.
- **Backtest lag:** any backtest conditioning on this regime must lag the
  label by ≥ `1` bar [default] (min_lag = `1` bar [default]; funding prints per interval; the label uses the latest settled interval).
- **Adversary check (no-lookahead):** the test suite asserts
  `label_ts > indicator_ts` for the earliest gated trade and that appending a
  synthetic breakout bar does not move the trailing window used at `t`.
- **unknown_behavior:** `UNKNOWN` is restrictive — downstream halves size /
  widens stops / stands down; never treated as benign (F1).

## §R1 Precise definition

Annualized funding `f_ann = f_8h × 3 × 365` (simple; `0.01% × 3 × 365 = 10.95%` [documented arithmetic]). Venue mechanics [documented]: `F = P + clamp(I − P, −0.05%, 0.05%)` where `P` is the time-weighted average premium index and `I = 0.01%` per 8h interval for most symbols; Bybit adds outer funding-rate upper/lower limits and switches to hourly settlement when a limit binds [documented]; Binance settles some symbols hourly [documented]; Coinbase applies funding hourly [documented].

Cross-venue indicator: per settlement interval, the cross-venue mean of per-venue settled rates over reporting venues (≥ `2` [default]); trailing mean over `3` intervals [default]. Sentinel = mean-based; Verifier = median-based; agreement within `0.3` rel. [default] or `UNKNOWN` (F3). Verifier additionally requires cross-venue sign agreement when `|f_ann| > 1%` [default] [documented RB-list].

## §R2 Exact calculation

$$f_{ann} = \bar{f}_{8h}\times 3\times 365 \quad\text{[documented]}$$

where $\bar{f}_{8h}$ is the trailing `3`-interval [default] mean of per-interval cross-venue means. Worked example [documented Grok RB2]: mean 8h rate `0.020%` → `0.00020 × 3 × 365 = 21.9%` ⇒ moderately elevated.

**Data inputs.** Settled venue funding prints + settlement frequency, per venue (`reported_funding_{venue}` [documented]).

**Cadence.** 8-hour; daily summary. Poll after settlement + `5` min [default].

### Normative detection pseudocode

```python
def detect(state, events, cfg) -> RegimeState:          # §R0.1
    prints = [e for e in events if valid(e)]            # need venue, f_8h, event_ts
    if not prints: return UNKNOWN("missing")           # F1
    if any(not finite(p.f_8h) for p in prints): return UNKNOWN("invalid")  # F1
    grid = align_to_8h_settlement_grid(prints, cfg)     # hourly venues: sum 8 hourly prints [default]
    # --- edge cases ---
    # missing bars: interval with < min_venues prints -> MASKED (never interpolated)
    # venue delisted / halted: drop venue; if < min_venues remain -> UNKNOWN (F1, restrictive)
    # settlement-frequency change mid-series: interval-length assertion fails ->
    #     DEGRADED, resync grid, require window_intervals valid intervals before OK
    # corporate actions: N/A for perps (no splits/dividends); analogs handled above
    vals, prev = [], "balanced"                        # hysteresis entry state [default]
    for t in grid.settlements:                         # causal order, event_ts <= t
        win = last cfg.window_intervals valid intervals ending at t
        if len(win) < cfg.min_intervals: label = ("warming", DEGRADED); continue
        cross = mean(venue_mean(v, win) for v in venues)
        v_ann = cross * 3 * 365 * 100                  # percent [documented]
        if abs(v_ann) > 1.0 and any(sign(venue_mean(v, win)) != sign(cross)):
            return UNKNOWN("sign-disagreement")        # F3 hygiene
        vals.append(v_ann)
        label = step(prev, v_ann, vals, cfg)           # hysteresis below
        prev = label
    return check_bounds_and_agreement(...)             # F2, F3, F4 in detect()

def step(prev, v, vals, cfg):                          # hysteresis state machine
    up = lambda thr: sum(1 for x in vals[-cfg.confirm_k:] if x >= thr) >= cfg.confirm_n
    if prev == "balanced":
        return "leaning" if up(cfg.lean_entry_ann) else "balanced"
    if prev == "leaning":
        if v < cfg.lean_exit_ann: return "balanced"     # exit: immediate
        return "crowded" if up(cfg.crowded_entry_ann) else "leaning"
    if prev == "crowded":
        if v < cfg.crowded_exit_ann: return "leaning"  # exit: immediate
        return "extreme" if up(cfg.extreme_entry_ann) else "crowded"
    return "crowded" if v < cfg.extreme_exit_ann else "extreme"   # from extreme
```

Entries need `2`-of-`3` confirmations [default] (a lone spike cannot flip the
label — pinned by the fixture's settlement-6 spike); exits fire on the first
evaluation below the lower exit threshold (no confirmation on the way down).

**Threshold bands (entry / exit, annualized %).**

| Condition | Label | Entry | Exit | Tag |
|---|---|---|---|---|
| `< 5%` / `< 4%` | balanced | `5.0` | `4.0` | [default] |
| `≥ 5%` / `≥ 4%` | leaning | `5.0` | `4.0` | [default] |
| `≥ 20%` / `≥ 15%` | crowded (reduce naked longs) | `20.0` | `15.0` | [default] |
| `≥ 50%` / `≥ 40%` | extreme (cascade risk) | `50.0` | `40.0` | [default] |

### Calibration recipe (no magic numbers)

Every threshold above is a `default`, not a fact. Calibrate as follows:

1. **Data:** `24` months [default] of settled 8h prints from `3` venues
   (Binance, Bybit, OKX); keep only intervals with ≥ `2` venues [default].
2. **Grid:** `lean_entry ∈ {3,…,8}` step `1`; `crowded_entry ∈ {10,…,30}` step
   `5`; `extreme_entry ∈ {40,…,100}` step `10`; `exit = entry × {0.7, 0.8}`;
   `window_intervals ∈ {3, 5, 9}`; `confirm ∈ {(1,1), (2,3)}`. All grid
   numerics [default].
3. **Objective:** out-of-sample funding-drag avoided (bps/year) for a
   reference unit-notional long book gated by the label, minus `2`× the
   turnover cost of label flips [default weighting] — maximize the median
   across folds.
4. **Validation:** walk-forward, ≥ `12` folds [default], fold = `3` months
   [default], embargo = `1` fold [default]; select the config with the best
   median and top-quartile stability across folds; freeze the winner.
5. **Re-calibration cadence:** quarterly [default]. Any threshold change ⇒
   semver bump + changelog entry. No ex-post period selection (F5).
6. **Current status:** the shipped defaults are grid-mode centers, **not yet
   calibrated on real data** — real-data calibration is an open item
   (GROK-NEEDED in the delivery report; unverified lead in §R10).

## §R5 Cost interface: regime state → cost-function adjustment

Funding is a direct holding-cost line on perpetuals (there is no borrow leg —
`borrow_bps_per_day = 0` with reason: perps have no expiry and funding replaces
borrow [documented]). The regime adjusts the cost function as follows:

| Cost component | Scales with regime? | How much (tagged) |
|---|---|---|
| funding (holding) | **yes — linear** | `funding_bps_per_day = funding_ann/100/365 × 1e4`: balanced `5%` → `1.37` bps/day; crowded `20%` → `5.48` bps/day; extreme `50%` → `13.70` bps/day [documented arithmetic] |
| spread | no (venue microstructure) | unchanged by R019; cascade widening is R023's flag |
| fees | no | taker `0.05%`/leg, maker `0.02%`/leg on Binance USD-M regular tier [unverified] — verify on the exchange fee page before trading |
| borrow | N/A | `0` — perps settle via funding, not borrow [documented] |
| impact | indirectly | regime gates size (`size_mult`), which lowers participation |

```python
def cost_adjustment(rsv, base):
    """Regime state -> cost-function adjustment. Positive funding_ann means
    longs pay: it is a cost for longs, a rebate for shorts."""
    adj = dict(base)
    f_ann = rsv['value'] / 100.0                       # annualized decimal
    adj['funding_ann'] = rsv['value']                  # direct P&L line [documented]
    adj['funding_bps_per_day'] = f_ann / 365.0 * 1e4   # [documented arithmetic]
    adj['size_mult'] = {'extreme': 0.25, 'crowded': 0.5}.get(
        rsv['state'], 1.0)                             # [default]
    adj['trade_ok'] = True                             # [default]
    return adj

def funding_leg_bps(notional, side, funding_ann_pct, hold_hours):
    """Expected funding cost in bps of notional for one planned hold.
    side = +1 (long) | -1 (short). Positive return = cost to the position."""
    return side * (funding_ann_pct / 100.0) * (hold_hours / 8760.0) * 1e4  # [documented arithmetic]

def funding_entry_gate(funding_ann_pct, hold_hours, edge_bps, k=0.5):
    """Executable predicate: block new longs when the expected funding drag
    over the planned hold exceeds k × edge."""
    return funding_leg_bps(1.0, +1, funding_ann_pct, hold_hours) <= k * edge_bps  # k [default]
```

Worked gate [example]: crowded `20%` funding, planned `72`h long hold,
`edge_bps = 30`: funding leg = `0.20 × 72/8760 × 1e4 = 16.4` bps >
`0.5 × 30 = 15` bps → gate blocks the entry; at balanced `5%` the leg is
`4.1` bps → passes.
