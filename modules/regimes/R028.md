## §R2 Precise definition

High-yield option-adjusted spread level and momentum — the market's summary statistic for default fear and risk appetite. Stress is a level *and* speed call: `OAS_t` plus its 20-session change. State is slow-moving; the Gate rejects chapters that day-trade off it.

### §R2.1 Normative detection pseudocode

Pseudocode is normative; prose is commentary. `cfg` is the §R0.2 dataclass;
`window` holds the last `21` [default] valid OAS prints (bps); `prev` ∈
`{CALM, WATCH, STRESSED}`; `run` counts consecutive benign bars for exits.

```python
for e in events:  # ascending event_ts; label at t uses only events[:t+1]
    ts = e.event_ts
    if e.market_state == HALTED:
        emit(ts, state="UNKNOWN", value=NaN, module_state="UNKNOWN")
        window.clear(); run = 0        # freeze prev; discard across reopen
        continue
    oas = parse(e.oas_bps)             # FRED Percent × 100, §R0.3
    if oas is None:                    # F1 missing / F2 non-finite / F2 negative
        emit(ts, state="UNKNOWN", value=NaN, module_state="UNKNOWN")
        continue                       # freeze prev/run/window; NEVER interpolate
    window.append(oas); window = window[-21:]
    if len(window) < 21:
        emit(ts, state="UNKNOWN", value=NaN, module_state="UNKNOWN")
        continue                       # warm-up: acute path blind; machine frozen at CALM
    chg = window[-1] - window[0]        # Δ_20 OAS, bps
    lvl = oas
    enter_stress = (lvl > cfg.stress_bps) or (chg > cfg.acute_chg_bps)
    if prev == CALM:
        prev = "STRESSED" if enter_stress else ("WATCH" if lvl > cfg.watch_bps else "CALM")
        run = 0
    elif prev == WATCH:
        if enter_stress:
            prev, run = "STRESSED", 0
        elif lvl < cfg.watch_exit_bps:
            run += 1
            if run >= cfg.confirm_bars: prev, run = "CALM", 0
        else:
            run = 0
    else:  # STRESSED
        clear = (lvl < cfg.stress_exit_bps) and (chg < cfg.acute_exit_bps)
        if clear:
            run += 1
            if run >= cfg.confirm_bars: prev, run = "WATCH", 0
        else:
            run = 0
    emit(ts, state=prev, value=chg, module_state="OK")
```

**Edge-case rules (all pinned by the 90-row fixture + tests).**

- **Exact-boundary rule:** all comparisons are strict. A print exactly on a
  band edge holds the current state (hysteresis zone): `350` bps [example]
  neither enters nor exits WATCH; `550` [example] does not enter STRESSED;
  `500` [example] does not exit STRESSED.
- **Missing bars (F1):** no print → `UNKNOWN`, machine frozen (counters do not
  accrue, no phantom exits); the next valid print resumes from the frozen
  state. Never interpolate across the gap.
- **Halts:** per §R0.5 — emit `UNKNOWN`, freeze the published label, clear the
  window and reset `run`; `21` [default] fresh post-halt prints are required
  before labels resume (re-warm).
- **Corporate actions:** OAS is an index, not a single name — the analog is an
  ICE index reconstitution or methodology change. Treat as a methodology
  break: freeze, emit `UNKNOWN`, page, and require manual re-arm after
  methodology review (see §R7). Constituent-level corporate actions are the
  vendor's problem, not the detector's.
- **Entry/exit asymmetry is deliberate:** entry is immediate (stress is
  urgent; a one-day spike to `552` [example] must gate the next open), exit
  requires `3` [default] consecutive benign bars (a dead-cat bounce must not
  re-arm risk).

## §R3 Exact calculation

$$\Delta_{20}\mathrm{OAS}_t = \mathrm{OAS}_t - \mathrm{OAS}_{t-20} \quad [\mathrm{bps}], \qquad
\mathrm{speed}_t = \Delta_{20}\mathrm{OAS}_t / 20 \quad [\mathrm{bp/day}]$$

Optional robust z on the change (second estimator):
$$z^{\mathrm{OAS}}_t = \frac{\Delta_{20}\mathrm{OAS}_t - \mathrm{med}(\Delta_{20}\mathrm{OAS})}
{\mathrm{MAD}(\Delta_{20}\mathrm{OAS}) \cdot 1.4826	ext{ [documented]}$$
Worked check: `OAS_t = 620` bps [example], `Δ_20 = +110` bps [example] → level
above `600` (stress zone), speed `+5.5` bp/day — fast widening → ON.

## §R4 Efficacy modulation

Direction ∈ `amplifies | degrades | inverts`; mechanism states *why*.

| Affected S/T families | Direction | Mechanism |
|---|---|---|
| T: credit-sensitive equity (high-beta, small-cap) | degrades | Merton: equity vol and credit spreads are two views of one leverage state — the equity is a junior claim on deteriorating credit |
| T: HY-carry | degrades | spread widening is mark-to-market loss on the carry book |
| S/T: safe-haven / quality factors | amplifies | quality and liquidity premia outperform in stress |

**Evidence notes.** The Merton mechanism is structural, not empirical: Merton
(1974), "On the Pricing of Corporate Debt: The Risk Structure of Interest
Rates," *Journal of Finance* [documented] models equity as a call option on
firm assets — when credit spreads widen, the junior claim (equity) is the
first to reprice. Conditioning evidence: Gilchrist & Zakrajšek (2012),
"Credit Spreads and Business Cycle Fluctuations," *American Economic Review*
102(4):1692–1720 [documented] — a bottom-up credit-spread index has
considerable predictive power for future economic activity, and shocks to the
excess bond premium lead to declines in economic activity and asset prices.
Caveat: GZ is monthly EBP, not daily HY OAS — it supports the conditioning
claim, not a strategy backtest.

## Cost interface: regime state → cost-function adjustment

The regime state maps to an adjustment record applied to the strategy's
`expected_cost_bps(notional, adv_pct, venue, side, urgency)` inputs. The record
is the *only* cost channel (no cost numbers are restated elsewhere).

```python
COST_ADJUSTMENT_R028 = {"regime_id": "R028", "version": "1.1.0", "STRESSED": {"spread_mult": 2.0, "impact_mult": 2.0, "borrow_mult": 1.5, "fee_add_bps": 0.0, "tag": "[example]"}, "WATCH": {"spread_mult": 1.25, "impact_mult": 1.25, "borrow_mult": 1.0, "fee_add_bps": 0.0, "tag": "[example]"}, "CALM": {"spread_mult": 1.0, "impact_mult": 1.0, "borrow_mult": 1.0, "fee_add_bps": 0.0, "tag": "[default]"}}
```

| State | Spread × | Impact × | Borrow × | Fee add (bps) | Applies when |
|---|---|---|---|---|---|
| STRESSED | `2.0` | `2.0` | `1.5` | `0.0` | OAS > `550` bps [documented] or acute widening |
| WATCH | `1.25` | `1.25` | `1.0` | `0.0` | `350–550` bps [documented] |
| CALM | `1.0` | `1.0` | `1.0` | `0.0` | identity |

**What scales and why** (magnitudes `[example]` — calibrate per venue; the
mechanism is the documented part).

- **Spread ×2.0 in STRESSED:** credit-sensitive equities (high-beta,
  small-cap) are the junior claim on the same deteriorating credit (Merton
  1974 [documented], §R4) — dealers widen quotes and pull size as default
  fear rises, so the taker spread component of `expected_cost_bps` scales up.
- **Impact ×2.0 in STRESSED:** book depth thins in stress; the same notional
  walks further down the book. Applies to the market-impact component only,
  not to fees.
- **Borrow ×1.5 in STRESSED:** borrow desks tighten supply and specials widen
  on HY-adjacent / high-beta names when credit stress is on; the
  `borrow_bps_per_day` input scales. WATCH leaves borrow at `1.0` [example] —
  mild spread widening alone does not reprice stock loan.
- **Fee add `0.0`:** exchange/regulatory fees do not move with credit regimes
  [default].

**Application rule.** `apply STRESSED/WATCH multipliers to credit-sensitive names' expected_cost_bps inputs; CALM = identity` All multipliers `[example]` unless
tagged otherwise — calibrate per venue against the desk's own slippage/borrow
marks; the record is versioned with `estimator_version` and every application is decision-logged (Appendix g
v1.0.0).

**Worked application** [example numbers end-to-end]. Base
`expected_cost_bps` stack for a credit-sensitive name:
`{spread: 8.0, impact: 6.0, borrow: 2.0, fee: 0.5}` bps [example]. Under
STRESSED the adjusted stack is
`{spread: 16.0, impact: 12.0, borrow: 3.0, fee: 0.5}` =
`{8.0×2.0, 6.0×2.0, 2.0×1.5, 0.5+0.0}` [example]; total `31.5` vs `16.5` bps
[example]. Under WATCH: `{10.0, 7.5, 2.0, 0.5}` = `20.0` bps [example] total.
The record applies to credit-sensitive names only — quality/safe-haven names
keep the CALM stack even in STRESSED (their spreads compress, not widen).
